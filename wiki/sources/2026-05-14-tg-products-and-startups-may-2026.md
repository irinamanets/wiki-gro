## Ключевые идеи

- **Stanford-исследование вайбкодинга** (6 000 сессий, 63K промптов, 355K тулколлов, янв–апр 2026) количественно подтверждает intuitions Бая: 41% сессий — чистый вайбкодинг (агент пишет >99% кода); только 44% сгенерированного кода доживает до коммита; чистый вайбкодинг в **9 раз чаще** создаёт security-уязвимости. → Усиливает [[canon/marketing-frameworks/harness-engineering-for-ai-agents]], даёт numerical proof-points для контент-хуков.
- **Slot-machine vs printer-стратегия GenAI** — новая дуальная рамка для оценки GenAI-продуктов. Слот-машина: больше пуллов = больше выручки (казино-бизнес, transitional rent, работает пока модели плохо детерминированы). Принтер: меньше попыток до результата = выше доверие = долгосрочная стратегия. Связан с понятием Loss Disguised as a Win из gambling (Rachel Thomas, fast.ai). См. [[canon/marketing-frameworks/slot-machine-vs-printer-genai-strategies]].
- **Generative UI — дизайн-система становится inference-системой**. Token, который раньше хранил цвет (`--color-primary: #0066FF`), теперь хранит **интент** (`--color-interactive-primary`). Дизайн-система перестаёт быть шпаргалкой для человека и становится API, который модель дёргает как tool-call. См. [[canon/marketing-frameworks/generative-ui-design-system-inference]].
- **CEO–CTO AI-adoption bridge** — типичный паттерн: CEO влюблён в Claude Code, давит на CTO ускоряться; CTO боится Stanford-историй и саботажа. Реальное решение — **разделять задачи на категории по цене ошибки**, инвестировать в верифицируемость (эвалы, тесты, голден-датасеты), и признать что **AI-разработка ≠ ускоренная разработка, это другая разработка**. См. [[canon/marketing-frameworks/ceo-cto-ai-adoption-bridge]].
- **AI Product Engineer 4-й поток** — Бай продолжает развивать свой курс на Empatika. Тематически: контекст-как-поверхность-программирования, недетерминированность LLM, Plan Mode + Constitution, SDK (Claude Agents / Codex / Cursor), сквозной демо-проект TARS. См. [[evolving/competitor-positioning/ai-product-engineer-course-empatika-2026]].
- **METR Mythos**: новая модель/конфигурация не помещается на графике METR — отметка ~16h+ при 50% надёжности. Signal: лидеры benchmark-а растут быстрее, чем растёт test suite. Существующая страница [[canon/marketing-frameworks/harness-engineering-for-ai-agents]] раздел 5 обновляется этой точкой.
- **Slide-inspector skill calibration pattern**: Бай добавил в свой open-source skill шаг **самокалибровки** — скилл анализирует прошлые Claude Code сессии пользователя на предмет pptx-исправлений и расширяет себя «фирменными» правилами. Это reusable архитектурный паттерн для skill design. См. [[canon/marketing-frameworks/claude-skills-architecture]] update.

## Факты и цифры

### Stanford-исследование (post 1740, arxiv 2604.20779)

Все цифры из самого пейпера + графики в attached/1740. Цитировать в `*-strict` слоях с маркером `[conf:high, src:2026-05-06]`:

- **Датасет:** 6 000 сессий, 63K промптов, 355K тулколлов из публичных репов; источники — Claude Code (большинство, Opus 4.6), OpenCode, Gemini, Factory; период янв–апр 2026
- **Use cases:** code understanding 19% (most common intent), debug 13%, refactor 9%, git 14%, create new code 13%, other 32%
- **Tool calls:** bash 33%, read/edit/search files 48%, остальное — другое
- **Vibecoding share:** 41% сессий — агент пишет >99% кода
- **Pure-human:** 23% — человек пишет всё сам
- **AI-code survival rate:** 44% при коллаборации; **в чистом вайбкодинге — 59%** (выше; авторы трактуют как «меньше ревью», а не как «лучше попадание»)
- **Code waste breakdown:** ~10% агент сам же переписывает (черновики), ~46% юзер удаляет/переписывает
- **Vulnerability rate (на 1000 строк):**
  - человек ручками: **0.08**
  - человек + агент в коллабе: **0.14**
  - чистый вайбкодинг: **0.76** (**~9× больше**)
- **Session success rate:** в среднем **82%**
- **User behavior:** Expert Nitpicker 40%, Vague Requester 33%, Other 20%, Mind Changer 7%
- **Agent push back behavior:** Agents stop 1%, User interruption 5%, User pushback 41%
- **Pricing (median $ / 100 committed lines):** Human-only $0.07, Collaborative $0.05, Vibe coding $0.13

### Slot-machine economy (post 1745)

- **Кейс клиента:** $150 слил на HeyGen-генерацию промо-ролика, нормального результата не получил
- **CC соотношение токенов:** 100:1 input/output `[conf:medium, src:2026-05-09]`
- **SemiAnalysis-термин «tokenmaxxing»:** ради качества бросают всё больше токенов на одну задачу
- **Цитата Kitze (talk):** «In casino you buy chips. Here you buy tokens. You spin the slots or you press generate. You might hit the jackpot or nothing.»
- **Rachel Thomas, fast.ai (2026-01-28):** «Loss Disguised as a Win» — паттерн мультилайн-слотов: ставишь 20 центов, получаешь 15 кредитов «обратно» с эффектами — мозг регистрирует как победу при фактическом минусе.

### Generative UI (post 1746)

- **YC RFS (Request For Startups):** dynamic software interfaces — публично заявлено
- **David Hoang цитата (proofofconcept.pub):** «Design systems are now inference [systems]»
- **Salesforce пример precedent'а:** constrained app-builder palette с 2014
- **Andrew Ng (DeepLearning.ai):** бесплатный курс «Build Interactive Agents with Generative UI»
- **Эрик фон Хиппель reference:** «Democratizing Innovation» (MIT), user-centered innovation framework — power-юзеры создают компоненты, агент помогает стандартизировать

### CEO–CTO bridge (post 1748)

- **3 категории задач по цене ошибки:**
  - **(a)** внутренние тулзы / прототипы / PoC / one-shot интеграции → разрешить вайбкодинг полностью
  - **(b)** customer-facing фичи, где цена ошибки << выигрыш от скорости → инвестировать в harness + эвалы
  - **(c)** платежи / безопасность / клиентские данные → не вайбкодить
- **4 типа инвестиций в верифицируемость:** автотесты, голден-датасеты, эвалы, системы обратной связи
- **Аналогия Бая:** разработка с дружбаном ≠ ускоренная разработка, это **другая разработка**; претензии к ней похожи на претензии к аутсорсингу

## Маркетинговые выводы

1. **Stanford-исследование = новые numerical hooks для GRO-контента**: «44% сгенерированного кода идёт в мусор», «1 из каждых ~12 сессий — pushback пользователя» (41% всё-таки преувеличение в обратную сторону — push-back ≠ stop), «vibecoding на $0.13/100 строк против $0.05 collaborative — почти в 3 раза дороже». См. готовые формулировки в [[evolving/content-trends/ai-product-engineer-content-hooks]] update.

2. **Slot-machine vs printer — каркас для конкурентного позиционирования GRO**. Если в продуктовом маркетинге надо отстраиваться от случайно-генеративных конкурентов («нагенерим тебе план тренировок!»), фрейм «принтер vs слот-машина» даёт **готовую антипозицию**: «GRO выдаёт результат с первого раза, а не заставляет крутить барабан». Хук применим в постах про любые GRO-AI компоненты.

3. **Generative UI = архитектурный паттерн для долгосрочного позиционирования продукта**. Если GRO планирует ввести AI-генерированный UI для персонализированных тренировочных интерфейсов — фреймворк Hoang о токенах-как-интенте (`--color-interactive-primary` вместо `--color-primary`) даёт правильную ментальную модель.

4. **CEO–CTO bridge — готовый контент для B2B-инфо-маркетинга**. Это **самый прямой material** для контента про внедрение AI в командах. Готовая структура: «3 категории задач», «инвестиции в верифицируемость», «договориться об identity-сдвиге программиста». Целевой сегмент: B2B founders, CMO, CMO агентств.

5. **Skill calibration pattern для нашей собственной memory**: idea для эволюции wiki-фреймворка — skill, который анализирует прошлые ingest-ы и предлагает обновление preset.themes / rules.md. Это **REFLECT, автоматизированный через self-observed pattern**.
