# GRO-Book «Инструменты продуктивности в эпоху ИИ»

Брендированный PDF-лид-магнит GRO (серия «GRO-Book»), приложенный к посту 396 канала [@gro_me](https://t.me/gro_me) от 28 мая 2026. Два полных гайда под одной обложкой: (1) сборка живого дашборда в Obsidian + Claude Code через MCP, (2) «NotebookLM Maxxing» — 27 кейсов, библиотека промптов, мастер-воркфлоу. Это собственный контент-актив бренда — образец того, как GRO упаковывает прикладной AI-контент и какой tone of voice использует в long-form формате.

## Релевантность

**Релевантно полностью** — собственный контент-актив GRO. Ценность:
- образец **формата лид-магнита** бренда (GRO-Book): прикладной, операционный, «бери и делай»;
- **tone of voice в long-form**: короткие декларативные блоки, code-блоки с реальными конфигами, принцип «читать, а не хранить»;
- **продуктовый сигнал**: GRO позиционирует себя в нише «AI + личная продуктивность предпринимателя», и этот гайд — материализация контент-разворота в utility/applied (см. пост 390 в [[evolving/content-trends/gro-content-rubrics-system]]).

## Содержание (краткое)

**Часть 1 — Дашборд в Obsidian + Claude Code.** Главный принцип: дашборд — это «не ещё одно место для хранения», а одна заметка, которая через Dataview-запросы читает свойства (YAML properties) остальных заметок и показывает актуальное состояние при каждом открытии («читать, а не хранить»). Шесть секций: приоритеты на сегодня, активные проекты (с completion %, deadline, next_action), ближайшие 7 дней, здоровье клиентов (health: healthy/attention/atrisk + MRR), незакрытые петли (конвенция `OPEN:` в ежедневниках), пульс выручки (sum MRR через inline-dataview). Единственный нужный плагин — Dataview; дисциплина — единообразные YAML-свойства по типам заметок (project/task/client/daily). Подключение Claude Code через Filesystem MCP даёт два усиления: (1) умный утренний AI-брифинг по n8n в 6:00 («что значат данные», не «что показывают»), (2) автообновление свойств по конвенции `DONE:`/`UPDATE:` при закрытии работы.

**Часть 2 — NotebookLM Maxxing.** Курс из 27 рабочих кейсов (база знаний/курсы → бизнес/контент → продвинутые техники), библиотека промптов (извлечение/синтез, верификация, Studio), внутренняя архитектура (6 слоёв), проверка качества, мастер-воркфлоу и выпускной проект. Превращает произвольные источники в структурированные знания, курсы, презентации, бизнес-регламенты.

## Маркетинговые выводы

- **GRO-Book — устойчивый формат лид-магнита бренда** (ср. трендбук ERA Capital, PDF-памятки по регуляторике в [[evolving/product-reception/gro-channel-content-history]]). Этот выпуск — самый «инструментальный» из серии: чистый how-to без inspirational-обёртки, конгруэнтен utility-shift'у контент-стратегии.
- **Продуктовое позиционирование расширяется в сторону «AI-операционализации личной работы»** — дашборд + Claude Code + NotebookLM. Это не сам продукт GRO, а демонстрация экспертизы бренда в смежной нише, удерживающая внимание AI-curious аудитории (Сегменты 1–2).
- **Tone of voice в long-form** — декларативные заголовки + реальные code/config-блоки + повторяющийся рефрен-принцип («читать, а не хранить»; «устаревшие свойства = устаревший дашборд»). Переиспользуемый паттерн для будущих GRO-Book.
- **CTA-механика поста 396:** «Делитесь с теми, кто до сих пор использует ChatGPT как Google поисковик» — share-trigger через лёгкое статусное противопоставление (ты уже умеешь больше).
