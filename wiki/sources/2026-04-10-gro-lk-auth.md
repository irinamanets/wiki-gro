# GRO — веб-кабинет, экран авторизации (lk.groapp.ru/auth/)

## Метаданные
- **Тип:** URL (HTML + React Native Web SPA, фреймворк Expo)
- **URL:** https://lk.groapp.ru/auth/
- **Дата добавления:** 2026-04-10
- **Дата fetch:** 2026-04-10
- **Автор / источник:** сам продукт GRO (first-party), команда marketing-memory owner'а
- **Экспертность автора:** verified — first-party продуктовая поверхность, дополняет лендинг `groapp.ru` и три стор-листинга
- **Sidecar note:** был — поле `comment` в `raw/links.md`: «веб-версия нашего приложения (личный кабинет)»
- **Sensitive flag:** не применимо — публичная страница регистрации, PII отсутствует в контенте страницы (только в формах ввода)

## Релевантность
Источник высоко релевантен. Это **четвёртая (и, судя по overview, последняя известная)** точка дистрибуции GRO: веб-версия личного кабинета на поддомене `lk.groapp.ru`, доступная без установки мобильного приложения. Релевантны:

- **Факт существования веб-версии** → `canon/product-knowledge` (новая страница `gro-web-app`)
- **Технологический стек фронтенда** (Expo = React Native Web) — редкий сигнал о том, что GRO — cross-platform React Native проект, где web-версия собрана из того же кодбейса, что iOS/Android. Для нас это важно не технически, а как объяснение, почему v1.6.14 вышла одновременно на все три мобильные стора: единая кодовая база → единый релизный цикл. Добавляется в `canon/product-knowledge/gro-app-overview`.
- **Типографика бренда** (Montserrat + Unbounded + SpaceMono, preload в head) → новая страница `canon/brand-guidelines/gro-typography` — это первый канонический сигнал о визуальной идентичности GRO, `brand-guidelines` до сих пор был пустым (см. gap в [[overview]]).
- **Структура онбординга**: регистрация по номеру телефона ИЛИ email с OTP-кодом, три consent-чекбокса (user agreement, PII, marketing opt-in) — сигнал об онбординге и о том, как выглядит top-of-funnel в веб-канале. Релевантно для контента и для [[canon/target-audience/gro-segments]] (какой первый экран видит пользователь).
- **Закрытие gap'а про `gro.pro`**: на web-кабинете используется **только `groapp.ru`** (страница и поддомен), домен `gro.pro` нигде не светится. Это дополнительный сигнал, что `gro.pro` — чисто legal/support mailbox (Android-сторы), а продуктовый/маркетинговый домен консолидирован вокруг `groapp.ru`. Закрывает одну из линий gap'а в [[overview]].
- **Не релевантно/неприменимо** (не уходит в слои): точные хэши бандлов Expo (`entry-2cacd46eb8fa0aae1253fefd36f65284.js`), список всех 19 TTF-файлов, CSS-модули. Это build-артефакты конкретного снапшота, не устойчивая информация.

**Tracks contradiction (ключевой ожидаемый вопрос).** В [[canon/product-knowledge/gro-app-overview#contradictions]] веб-кабинет был записан как возможный путь верификации разнобоя треков между лендингом (продажи/маркетинг/коммуникации/цели/мышление/мотивация) и тремя сторами (карьера/деньги/коммуникации/мышление/фокус/продуктивность). Этот ingest **contradiction не закрывает**: экран `/auth/` — pre-auth, треки там не отображаются. Единственные семантические элементы страницы — форма регистрации, три чекбокса, cross-sell на мобильные приложения и ссылки на legal-документы. Чтобы закрыть contradiction, нужен post-auth ingest (личный кабинет после входа), а он требует реального аккаунта и не может быть сделан через WebFetch на публичном URL. Гипотеза «лендинг устарел» остаётся доминирующей, но **не подтверждается** веб-кабинетом.

## Ключевые идеи

- **Веб-версия GRO существует** и живёт на поддомене `lk.groapp.ru`. Это четвёртая точка дистрибуции помимо App Store, Google Play и RuStore.
- **Стек — Expo (React Native Web).** GRO — кросс-платформенный React Native проект, web собран из того же кодбейса. Это объясняет синхронный релиз v1.6.14 на всех сторах.
- **Точка входа** — `/auth/` (не `/`). Корневой `/` отдаёт пустой shell. То есть **реальный `lk.groapp.ru` URL**, который видит новый пользователь — это `lk.groapp.ru/auth/`.
- **Онбординг веб-канала:** регистрация с нуля через телефон/email + OTP-код, три consent-чекбокса, cross-sell на мобильные приложения. Логина для существующих пользователей на этом экране нет (надпись «Введи телефон или email для **регистрации**») — этот экран **однозначно позиционирован как регистрация новых пользователей**, а не как универсальный login/signup.
- **Brand voice на экране регистрации:** заголовок «**Сохраним твою точку старта**» — мета-обращение к growth-нарративу продукта: регистрация = начало трекинга роста, а не просто «создание аккаунта». Это сильный микро-копирайтинг сигнал, переиспользуемый в контенте.
- **Cross-sell на мобильное приложение** прямо на экране регистрации: «GRO всегда под рукой. Скачай приложение, если удобнее работать с телефона.» Команда явно видит веб-канал как **дополнительный**, а не основной: на входе в веб пользователю сразу предлагают мобильное приложение.
- **Типографика бренда:** Montserrat (8 весов от Thin до Black + италики), Unbounded (Regular), SpaceMono (Regular). Три шрифта — классическое разделение sans/дисплей/моно. Первый каноничный сигнал о визуальной идентичности GRO.
- **Legal-документы хостятся на самом `lk.groapp.ru/documents/`**, а не на отдельном доменe: `/documents/soglasie`, `/documents/personal`, `/documents/politika`, `/documents/oferta`. Это подтверждает, что веб-кабинет — не просто клиент, а и noscript-legal-хостинг для всего продукта.
- **HTML-lang = `en`** при 100% русскоязычном контенте — SEO/A11y техдолг (аналогично SEO-ghost в Google Play). В head нет `<title>`, нет OG-тегов, нет favicon кроме `/favicon.ico`, нет meta description. Для SEO-анализа веб-кабинет не оптимизирован (но это pre-auth форма, так и должно быть — её не должны индексировать).
- **Закрытие gap'а по домену `gro.pro`:** на веб-кабинете нигде не используется. Подтверждает, что `gro.pro` — узко legal/support mailbox (Android-сторы), продуктовый домен консолидирован вокруг `groapp.ru`.

## Факты и цифры

- **URL:** `https://lk.groapp.ru/auth/`
- **HTTP status:** 200 (direct GET, без редиректа)
- **Content size:** ~145 KB HTML (SSR shell + inline CSS с определением @font-face)
- **HTML lang:** `en` (при 100% ru-контенте — техдолг)
- **Фреймворк:** Expo (React Native Web) — определено по путям `/\_expo/static/js/web/entry-*.js` и `/\_expo/static/css/web-*.css`
- **Шрифты (preload):** Montserrat × 8 весов + italic-пары, Unbounded Regular, SpaceMono Regular
- **Legal-документы (все хостятся на `lk.groapp.ru/documents/`):**
  - `/documents/soglasie` — Пользовательское соглашение
  - `/documents/personal` — Согласие на обработку персональных данных
  - `/documents/politika` — Политика конфиденциальности
  - `/documents/oferta` — Согласие на получение рекламно-информационных рассылок
- **Корневой `/` на том же поддомене:** отдаёт пустой Expo shell без SSR-контента (только текст «Уведомление об успехе» из toast-компонента). То есть `/auth/` — это URL с явным SSR для поисковиков/пререндеринга, остальная часть SPA скрыта за client-side роутингом.

## Распознанный текст

Экран регистрации состоит из следующих блоков (по порядку появления в SSR-HTML):

1. **Заголовок:** «Сохраним твою точку старта»
2. **Подсказка к полю:** «Введи телефон или email для регистрации»
3. **CTA-кнопка:** «Получить код»
4. **Чекбокс 1:** «Я подтверждаю, что прочитал(а) и принимаю условия [Пользовательского соглашения](/documents/soglasie)»
5. **Чекбокс 2:** «Я даю [согласие](/documents/personal) на обработку моих персональных данных на условиях [Политики конфиденциальности](/documents/politika)»
6. **Чекбокс 3:** «Я даю [согласие](/documents/oferta) на получение рекламно-информационных рассылок»
7. **Cross-sell блок (появляется дважды в SSR — вероятно mobile + desktop варианты одного компонента):** «GRO всегда под рукой. Скачай приложение, если удобнее работать с телефона»
8. **Toast-шаблон (скрыт в норме):** «Уведомление об успехе»

Изображения на странице отсутствуют (все визуальные элементы — SVG/icon-компоненты, отрисованные client-side, в SSR-снапшоте их нет).
