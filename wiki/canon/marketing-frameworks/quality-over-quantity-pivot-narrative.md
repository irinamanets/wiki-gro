# Narrative-pivot pattern: «даёшь X → даёшь рентабельный X»

Communication-pattern для **внутреннего pivot'а команды** от количественной/мобилизационной метрики к качественной/экономической. Формализован по случаю Череповецкого металлургического завода 1956 года, когда после критики на 20 съезде КПСС команда поменяла внутренний лозунг с **«даёшь чугун»** (объём как KPI) на **«даёшь рентабельный чугун»** (экономика как KPI). За этим pivot'ом последовали измеримые результаты: себестоимость снижена ~15%, объём вырос на 53%, убытки уменьшились на 36,2 млн ₽ (1956 цифры) `[conf:medium, src:2026-05-06]`.

Pattern полезен как **template коммуникации внутреннего изменения стратегии** — особенно когда команда привыкла к одному типу метрики и нужно перевести на другой без disengagement'а.

`confidence: low` — pattern сформулирован по **одному case-study** (советский комбинат 1956) из вторичного источника. Не верифицирован против современных corporate change-management кейсов. Требует валидации против минимум 3 независимых post-Soviet и/или западных pivot-narratives.

## Структура pattern'а

Лозунг состоит из 3 частей: **императив + базовый объект + квалификатор**.

```
[императив] [базовый объект] [квалификатор качества]
   даёшь        чугун             —
   даёшь        чугун          рентабельный  ← pivot
```

**Императив остаётся прежним** (мобилизационная форма уже понятна команде), **объект тот же** (нет confusion «что мы делаем»), но **квалификатор** сдвигает внимание с «больше / быстрее» на «лучше / экономичнее».

Это критический design-choice: если бы лозунг изменили на «даёшь прибыль» или «даёшь модернизацию», сотрудники потеряли бы привязку к конкретной операционной деятельности. Сохранение базового объекта (чугун) + добавление квалификатора (рентабельный) = **continuity + evolution**.

## Современные применения pattern'а

### B2B / SaaS pivot

| До | После |
|---|---|
| «делаем больше features» | «делаем более используемые features» |
| «увеличиваем MAU» | «увеличиваем engaged MAU» |
| «закрываем deals» | «закрываем deals с правильным ICP» |

### B2C / consumer pivot

| До | После |
|---|---|
| «больше installs» | «больше completed onboarding'ов» |
| «больше posts в день» | «больше posts с engagement >X» |
| «больше signups» | «больше signups, которые активируются за 48ч» |

### GRO как кейс (potential)

Если GRO в какой-то момент будет переходить с «больше тренировок в день» на «больше тренировок с прогрессом» (выявленным через метрики формы / формы рекомендации) — это будет канонический применение pattern'а.

| До | После |
|---|---|
| «делай тренировку в день» | «делай прогрессирующую тренировку в день» |
| «открыл приложение» | «открыл и завершил тренировку» |

Хотя на 2026-05 GRO ещё не находится в pivot-фазе.

## Pre-conditions (когда pattern применим)

1. **Команда уже работает в одном лозунговом ритме** — pattern overrides существующего лозунга, а не вводит на пустом месте.
2. **Базовый объект действительно остаётся неизменным** — мы продолжаем делать «X», а не пивотим в другую категорию. Если меняется и объект, нужен другой communication-pattern (full re-orientation, см. [[canon/marketing-frameworks/internal-change-communication-protocol]]).
3. **Качественный квалификатор измерим** — «рентабельный» определялся через себестоимость, объём, убытки. Без операционных метрик квалификатор превращается в moralizing.
4. **Лидер готов модельно демонстрировать pivot** — pattern работает, когда CEO / CFO сам начинает использовать новый лозунг и связанный с ним vocabulary, а не просто «продвигает» на letterhead'е.

## Anti-patterns

| Anti-pattern | Что произойдёт |
|---|---|
| Сменить ВЕСЬ лозунг (включая объект) | Команда теряет continuity, появляется confusion и disengagement; сопротивление |
| Качественный квалификатор без операционных метрик | Превращается в moralizing — «работайте усерднее» — что демотивирует |
| Pivot без communication-runway | Команда воспринимает как очередную campaign'у; неверится; saboteurs формируются |
| Pivot за один speech / town-hall | Pattern требует **месяцев непрерывного reinforcement'а** через все каналы коммуникации |
| Использовать pattern для трюка (поменять только лозунг, без реальной смены KPI) | Команда быстро вычисляет — это даёт долгосрочный trust-loss |

## Связь с другими pivot-механиками

- **vs full re-orientation**: full re-orientation меняет и объект, и квалификатор (например, «делаем металл → делаем решения для клиентов»). Это другой pattern, для другой ситуации (см. узел 7 в [[canon-strict/historical-campaigns/severstal-cherepovets-transformation]] — Северсталь делала такой re-orientation в 2009).
- **vs zero-to-one pivot**: zero-to-one (например, [[canon/marketing-frameworks/zero-to-one-vs-scale-tabunov]]) меняет всю стратегию компании. Quality-over-quantity pivot работает **внутри уже работающей операции**.
- **vs change-management protocol**: [[canon/marketing-frameworks/internal-change-communication-protocol]] — общий протокол коммуникации изменений. Quality-over-quantity — это **специфический подтип** narrative-pivot'а внутри protocol'а.

## Применимость к GRO-контенту

- **Hook про operational pivot для founder-сегмента ЦА** ([[canon/target-audience/ru-smb-founder-owner-seller]]): «Завод на 20 съезде партии чуть не закрыли. Команда поменяла одно слово в лозунге, и за 5 лет вышли из убытка». Готовый narrative для post / video.
- **Template для коммуникации pivot'ов GRO внутри команды**: при переходе с retention-метрик на engagement-quality pivot, при переходе с installs на completed-onboardings, и т.д.
- **B2B-контент про operational excellence**: pattern полезен как frame для разбора, как зрелые компании коммуницируют внутренние изменения.

## Caveat

- Pattern сформулирован по **одному кейсу** (Северсталь 1956) из вторичного источника.
- 1956 цифры (15% / +53% / -36,2 млн ₽) — советские, возможна предвзятость пропаганды.
- Pattern может выглядеть **обманчиво простым** — на практике сила лозунга в его окружающей системе (KPI, incentive structure, model behavior лидера, retention структура), не в самом лозунге.
- Не применять как «достаточно поменять один слайд в дашборде» — pattern требует системной смены метрик.
