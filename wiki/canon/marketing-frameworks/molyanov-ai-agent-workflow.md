# Молянов: правила работы с ИИ-агентами

Практическая методология из опыта Павла Молянова (директор «Сделаем», основатель Нейроцеха, verified expert tier 2) — правила для получения качественных результатов от ИИ-агентов без экспертизы в программировании. Страница — canon: принципы устойчивы к смене конкретных моделей (Claude Code, Cursor, Copilot), т.к. описывают метауровень работы.

Смежная страница — [[canon/marketing-frameworks/spec-driven-agent-development]] (более ранняя методология Молянова про spec-driven подход). Эта страница фокусируется на **операционных правилах качества** во время исполнения.

## Основной тезис: «нейропирамида» требует валидатора

По мнению Молянова, ключевой риск внедрения нейросетей — отсутствие эксперта-валидатора на вершине цепочки:

> «Нейронка действительно может сделать что угодно... Вот только с большой вероятностью она сделает какое-то говно» — Молянов

Без человека, который понимает предметную область и проверяет результат, AI даёт некачественный вывод в маркетинге, продажах, блогах, разработке. «Нейропирамида» без вершины — ненадёжна.

Маркетинговый угол для GRO: этот тезис резонирует с позиционированием [[canon/positioning/gro-value-proposition]] — инструмент для тех, кто хочет думать и делать сам, а не делегировать «роботу» вслепую.

## 4 принципа качественной работы с ИИ-агентами

По мнению Молянова:

1. **Минимизировать контекст** — скармливать агенту только нужные части кода, документов, данных. Чем больше лишнего в контексте, тем хуже фокус.
2. **Бить задачи на мелкие этапы и сбрасывать контекст после каждого** — масштабные задачи должны разбиваться последовательно, не попыткой сделать всё в одном промпте.
3. **Явно прописывать критерии готовности** — агент должен знать, как выглядит «готово», иначе он остановится на «работает по-моему».
4. **Запускать субагентов-проверяльщиков** — после каждого этапа отдельный агент ищет уязвимости, ошибки, неточности. Это «quality gate loop».

## Самопроверочный паттерн для Claude Code

Молянов описывает конкретный паттерн усиления качества в Claude Code через встроенную самопроверку:

- **План написан** → субагент проверяет план
- **Код написан** → субагент ищет уязвимости и ошибки
- **Информация найдена** → субагент оценивает достоверность источников

По словам автора: «скорость работы выросла существенно, количество переделок упало в разы».

## MVP-подход в вайбкодинге

Молянов рекомендует **начинать с минимального работающего продукта** и последовательно добавлять функции, а не пытаться реализовать всё сразу:

> «начинать с минимального работающего продукта и последовательно добавлять функции, а не пытаться сделать все сразу — иначе гарантирован провал»

## Непрерывное улучшение через «планёрки»

Практика Молянова: инструктировать агента сохранять все случаи недовольства и переделок в отдельный файл. Раз в неделю — «планёрка» с агентом для обновления инструкций на основе накопленного.

Это система постепенной персонализации агента под конкретный рабочий контекст — аналог онбординга нового сотрудника.

## Инструментальный стек Молянова

По состоянию на начало 2026 г.:

- **Claude Code** — основной инструмент для всей разработки
- **Ассистент на базе Claude Code** — для задач и заметок
- **Приложение Claude** — для бытовых вопросов

В Нейроцехе новых резидентов отговаривают от ChatGPT в пользу Claude: «В разы умнее ChatGPT, и эта разница видна сразу, с первого промта».

## SaaS останется

Контрнарратив к vibe-coding-хайпу, важный для GRO-позиционирования:

> «Большинство людей не хотят тратить часы на продумывание логики и тестирование — им проще взять готовое решение за 1000 рублей, чем делать самим»

Рынок готовых SaaS-сервисов не исчезнет из-за вайбкодинга. Это поддерживает позиционирование GRO как «возьми и пользуйся», не «сделай сам».

## Маркетинговые выводы для GRO

- Тезис «нейропирамида без вершины» → **hook для аудитории B (менеджеры/предприниматели)**: «ты должен понимать задачу сам — AI не заменит экспертизу, он её умножает»
- 4 принципа Молянова → **content material** для обучающих постов/статей: «как правильно ставить задачи ИИ»
- Тезис про SaaS → **anti-FOMO content**: «не нужно кодить самому, чтобы использовать AI для работы»
