# AI-Native dev methodology — кейс CAIO в международном финтехе

Методологическая рамка из кейса Андре (Chief AI Officer в международной финтех-компании, авторский канал [@andre_dataist](https://t.me/andre_dataist), сайт [dataist.ai](https://dataist.ai/cases/ai-native-dev-250/)). Анонс через [@techsparks 5598](https://t.me/techsparks) 14 мая 2026.

**Экспертный статус.** Андре — verified expert: CAIO роль в действующей международной финтех-компании, преподавал курс по AI-Native разработке в университете Пафоса (Кипр) совместно с JetBrains, ведёт авторский канал @andre_dataist. Кейс задокументирован в публичной статье с цифрами и структурой. `confidence: medium` (методология описана автором как retrospective, без независимого аудита; цифры — самоотчётные).

## Основной кейс — 3 месяца, −250 инженеров, +20–40% скорость релиза

**Стартовая позиция:**
- ~500 инженеров в международной финтех-компании
- Старая модель: «компания держит 500 инженеров и всё равно двигается медленно»
- **Симптомы**: знания в головах людей, документация устарела, требования собираются по чатам, никто не понимает архитектуру целиком, AI-инструменты только **ускоряют существующий хаос**

**Результат через 3 месяца:**
- **Ускорение релиза новых фичей минимум на 20%** `[conf:medium, src:2026-05-14]`
- **Среднее ускорение — 40%** `[conf:medium, src:2026-05-14]`
- **В некоторых кейсах — от ×2 до ×4** `[conf:medium, src:2026-05-14]`
- **Сокращение ~250 из 500 айтишников** `[conf:medium, src:2026-05-14]` (половина команды не смогла перейти в новую модель)

**Причина сокращений:** «где-то мешала старая инженерная культура, где-то — открытый или скрытый саботаж. Обучение в формате хакатонов, буткемпов и интенсивов быстро показывает, кто способен учиться, управлять агентами и брать ответственность».

## Главный принцип

> «AI-Native разработка начинается с правильно оформленной спецификации.»

Не «промпт-инженерия», не «генерация кода кусками», не «вайб-кодинг». Спецификация — **центр управления процессом**.

## Структура методологии

### Phase 1 — Восстановление AS-IS (агент-археолог)

Восстанавливает **текущее состояние системы**:
- Архитектура
- Зависимости
- Нюансы работы с legacy

Без этого этапа агенту нельзя доверять code-generation — он не знает, что ломает.

### Phase 2 — Описание TO-BE (агент-аналитик)

Превращает спецификацию в **центр управления**:
- Фичи
- Пользовательские истории
- Описание поведения системы в виде **сценариев использования (use cases)**
- Требования

### Phase 3 — Change Request (агент-менеджер)

**Change Request связывает AS-IS и TO-BE**. Агент-менеджер составляет план разработки.

### Phase 4 — Требования с ID

Требования получают **ID** и **мэтчатся с тестами, задачами, релизами и метриками**. Это **traceability layer** — без него agentic flow рассыпается на хаос.

### Phase 5 — TDD на всех уровнях

Тесты **обязательны на всех уровнях архитектуры**: переход к **Test-Driven Development** становится обязательным условием, не опцией.

### Phase 6 — Code (агенты)

Только **после** прохождения Phase 1–5 агентам можно доверять написание кода.

### Phase 7 — Организационные изменения

- Стандартизация спецификаций
- Дашборды traceability
- Обучение новым ролям
- Постепенная сборка новой культуры разработки

См. [t.me/andre_dataist/240](https://t.me/andre_dataist/240) для детализации орг-изменений.

## Новая роль — AI Product Engineer

Андре формализует новую роль: [AI Product Engineer](https://t.me/andre_dataist/225).

> «Человек управляет продуктом целиком: ставит задачи агентам, управляет контекстом, принимает архитектурные решения, проверяет результат и несет ответственность за весь продукт.»

Это **не AI-engineer** (узкий ML-специалист) и **не product manager** (вне технического слоя). **Это новый гибрид**: полная ответственность за продукт + операционное управление агентами.

**Параллель:** «Мы же не пишем двоичный код, а пользуемся высокоуровневыми языками программирования — а сегодня используем естественный язык».

## Связь с другими методологиями вики

### Совместимость со spec-driven Молянова

Методология Андре **операционно близка** к [[canon/marketing-frameworks/spec-driven-agent-development|spec-driven agent development Молянова]]:

| Аспект | Молянов (Нейроцех) | Андре (CAIO) |
|---|---|---|
| Контекст | Малый/средний бизнес, агентство | Международный энтерпрайз |
| Команда | 1–10 (founder + AI-агенты) | 500→250 инженеров |
| Главный принцип | Маленькие шаги + проверка субагентами | Спецификация как центр управления |
| Quality gate | Субагенты после каждого шага | TDD на всех уровнях + traceability ID |
| Discovery | Интервью с человеком | Агент-археолог (AS-IS) |
| Изоляция | Новая задача = новый чат | Change Request + scoped tasks |

**Не противоречат**, а **масштабируются друг через друга**:
- Молянов — **bottom-up** для соло-предпринимателя / агентства
- Андре — **top-down** для enterprise с легаси и компанд-эффектом 500+ инженеров

### Cross-fertilization

[[canon/marketing-frameworks/peregudov-vibecoding-founder-playbook-2026|Vibecoding founder playbook Перегудова]] — это **anti-pattern** относительно обеих методологий (vibecoding без специ → быстро теряют контроль). Андре прямо это диагностирует: «Большинство людей сегодня учатся разрабатывать продукты с ИИ неправильно: они учатся писать промпты, генерировать куски кода и быстрее выполнять старую работу, либо делают это без спецификаций и тестов».

## Применимость для маркетинга GRO

### Content-hook'и

1. **«AI-Native dev начинается со спеки, не с промпта»** — opening hook для content про **методичность работы с AI-инструментами**. Параллель: GRO как продукт тренирует **методичность целеполагания**, не подменяет её AI-pomocnikom.
2. **«−250 инженеров за 3 месяца — но не ради сокращений»** — counter-hook к простой «AI сокращает рабочие места» нарративе. Реальный нарратив: **half команды не смогла адаптироваться, не AI их уволил**. Это для **сегмента карьеристов** GRO — снимает страх замещения, добавляет **operational требование** к адаптации.
3. **«AI Product Engineer — новая роль 2026»** — карьерный hook. Можно делать content про **«как стать AI Product Engineer»** — близкий по структуре к [[evolving/content-trends/ai-product-engineer-content-hooks|существующим AI-PE контент-хукам]].
4. **«Хаос + AI = ускоренный хаос»** — meta-hook про **операционную дисциплину**. Точно ложится в [[canon/positioning/gro-value-proposition|позиционирование GRO]] как продукта **системности**, не **усиления существующих привычек**.

### Antipattern

- **Не цитировать цифры −250 / +20–40% / ×2-×4 без квалификации**: это **один кейс одного CAIO** в **одной международной финтех-компании**. Использовать как **иллюстративный proof-point**, не как индустриальный бенчмарк.
- **Не путать «AI-Native dev» с GRO-продуктом** напрямую — методология про **разработку программных продуктов**, GRO — про **самоуправление и постановку целей**. Параллель работает на **мета-уровне** (системность + спецификация + traceability), не на **операционном** (GRO не делает code-generation).
