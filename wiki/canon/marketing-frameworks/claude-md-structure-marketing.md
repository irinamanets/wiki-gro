# CLAUDE.md structure — брифинг для Claude Code / Cursor

`CLAUDE.md` — файл контекста, который [Claude Code](https://claude.com/claude-code) автоматически читает в начале каждой сессии. Это **брифинг для агента**, аналогичный рабочему ТЗ для нового сотрудника-фрилансера. Без него каждая сессия начинается «с комы» — агент не помнит ни проекта, ни правил, ни того, что уже сделано, и первые 10 минут уходят на объяснения, а не на работу.

Важен для маркетолога потому же, почему `harness engineering` важен для разработчика: это **единственный способ делать воспроизводимую работу с агентом**, не зависящий от памяти одного конкретного чата. Иначе каждая ночь вайбкодинга — это лотерея.

Источник: Р. Кумар Виас, [[sources/2026-04-14-tg-solokumi-nov2025-apr2026|@solokumi]] пост 393 (2026-04-06), развитие темы в посте 395 (2026-04-10) и 397 (2026-04-14). Практика опирается на [живую подборку примеров](https://github.com/josix/awesome-claude-md) от сообщества.

Это canon: сама 5-блочная структура — стабильная инженерная рекомендация на всю эпоху IDE-агентов. Конкретные примеры инструментов (Cursor, Claude Code, Codex, Antigravity) — evolving.

## Два уровня файла

1. **Глобальный** (`~/.claude/CLAUDE.md`) — запоминает **личные предпочтения на все проекты вообще** (язык ответов, стиль общения, какие вещи всегда делать / не делать)
2. **Проектный** (`<project>/CLAUDE.md`) — знает всё про **конкретный проект**

**Правило приоритета:** проектный > глобальный. Если они противоречат, Claude следует проектному.

## Жёсткий лимит

**После ~200 строк Claude начинает хуже соблюдать файл.** Это не технический лимит — это эмпирическое наблюдение. Практический вывод: писать **только то, без чего агент 100% ошибётся**, всё остальное — в отдельные справочники, на которые файл ссылается.

Этот 200-строчный лимит — тот же самый инвариант, что в `wiki/rules.md` («держи L1 компактным, <200 строк»). Это общая закономерность работы с контекстом LLM: **после определённого объёма модель перестаёт уделять внимание инструкциям**.

## Три вопроса, которые должен закрыть файл

| Вопрос | Что означает для маркетолога |
|---|---|
| **ЗАЧЕМ** | Кто вы и какая цель проекта. Профессиональный контекст агенту. |
| **ЧТО** | Карта проекта: что уже есть, что нельзя трогать. |
| **КАК** | Правила, стиль, тон. Как агент должен принимать решения и писать тексты. |

## 5 блоков канонической структуры

### Блок 1 — Кто вы и что за проект

Один абзац, объясняющий, **чем занимается проект** и **кто вы как пользователь**. Это меняет, как Claude с вами разговаривает и какие решения предлагает.

> Пример: «Я маркетолог, делаю бота для сбора заявок с сайта, не разработчик, объясняй всё простыми словами и без кода, если я не прошу кода.»

Этот блок самый дешёвый и самый полезный. Он экономит десятки минут на каждой сессии, потому что убирает необходимость каждый раз объяснять уровень экспертизы и тип решений, которые вы хотите получать.

### Блок 2 — Что нельзя трогать без спроса

Части проекта, которые **уже работают и не должны переделываться**: платёжная страница, база с клиентами, логика рассылок, продовые API-ключи, конкретные CSS-классы с брендингом. Явное перечисление красных линий.

Один раз написал «в этот раздел без моей команды не лезь» — и больше не будет сюрпризов в виде внезапно переделанной формы оплаты.

### Блок 3 — Правила по стилю и тону

Здесь **вайб-описания работают отлично**, никакого кода не нужно. Формулировки естественным языком:

- «Общайся как живой менеджер, разговорным языком, используй сленг»
- «Сделай форму более отзывчивой»
- «Сделай текст теплее»

Claude понимает это не хуже точной спецификации. Не нужно упарываться в формулировки — агент работает по семантике, а не по синтаксису.

В этот блок в marketing-контексте попадают: **TOV бренда**, запрет/разрешение мата, язык ответов, форматы контента (пост/рилс/рассылка), запрет прямых CTA в полезном контенте (см. [[evolving/content-trends/telegram-native-formats|telegram-native-formats]]), обязательные дисклеймеры по юр-требованиям ([[canon-strict/legal-claims/ad-marking-russia-2026]]).

### Блок 4 — Чем занимаетесь прямо сейчас

**Короткая** заметка про текущую задачу:

> «Сейчас делаем форму регистрации на вебинар, всё остальное не трогаем.»

Зачем блок: Claude **не будет предлагать улучшить то, чего вы не просили**, и не потеряет контекст между сессиями. Убирает самую частую фрустрацию — агент «помогает» переделать что-то, что не нужно было менять.

Этот блок — **живой**, его надо обновлять каждые 1–3 дня. В идеале — из того же чата, где вы работаете с агентом: «Обнови блок 4, мы теперь делаем X».

### Блок 5 — Что уже сделано и работает

Список готового. Зачем: агент не предлагает переделать уже работающие процессы и **не тратит токены** на «давайте улучшим то, что вы сделали на прошлой неделе». Фокусирует ресурс на приоритетных задачах.

В этот блок хорошо падают ссылки на артефакты: готовые лендинги, развёрнутые агенты в n8n, собранные датасеты AJTBD, рабочие фабрики контента, сделанные кампании.

## Как заполнить с нуля

1. Вручную — написать 5 блоков, укладываясь в 200 строк, опираясь на [awesome-claude-md](https://github.com/josix/awesome-claude-md) как подсказку по жанру
2. Автоматом — запустить команду **`/init`** в Claude Code. Агент изучит ваш проект и сгенерирует черновик, который останется подправить под себя. Гайд: [blog.vincentqiao.com/en/posts/claude-code-init](https://blog.vincentqiao.com/en/posts/claude-code-init/)

## Claude Code расширенные возможности

Дополнение от 2026-05-05 на базе постов 395 (2026-04-10) и 397 (2026-04-14) во втором дампе [[sources/2026-05-05-tg-solokumi-redump-dec25-apr26|@solokumi]]. CLAUDE.md — корневой брифинг, но Claude Code сам по себе содержит набор продвинутых команд, которые расширяют его возможности при правильно настроенном `CLAUDE.md`:

### MCP-серверы — внешние инструменты

`claude mcp add <ссылка>` — подключение к внешним сервисам (Figma, Calendar, GitHub, Notion, Telegram, базы данных). Каталог MCP-серверов: [github.com/punkpeye/awesome-mcp-servers](https://github.com/punkpeye/awesome-mcp-servers). Через MCP агент работает не через копи-паст, а реально заходит в сервисы, читает данные, выполняет действия. См. [[canon/marketing-frameworks/claude-skills-architecture|Claude Skills]] про правильный паттерн использования MCP в скиллах.

### Параллельный запуск агентов

Claude Code умеет запускать **дочерние копии себя**, работающие параллельно. Активируется промптом «сделай параллельно через несколько агентов». Скорость растёт линейно от количества агентов; токены тоже растут линейно, поэтому выгодно для задач, где сериализация даёт критичную задержку (анализ 3 рекламных кабинетов одновременно vs последовательно).

### Hooks — автоматические скрипты на действия

Скрипты, запускающиеся в ответ на действия Клода: «агент сохранил файл — хук запускает тесты», «Клод закончил задачу — хук отправляет уведомление в Telegram», «агент собрался запустить опасную команду — хук блокирует и спрашивает». Гайд: [blakecrosley.com/blog/claude-code-hooks-tutorial](https://blakecrosley.com/blog/claude-code-hooks-tutorial).

### `/init` — генерация CLAUDE.md с нуля

Команда `/init` в Claude Code: агент сам изучает проект и генерирует черновик `CLAUDE.md`. Подправляешь под себя, экономишь час ручной работы. Гайд: [blog.vincentqiao.com/en/posts/claude-code-init](https://blog.vincentqiao.com/en/posts/claude-code-init/).

### `/think` — расширенное мышление

Перед сложным запросом: `/think` — Claude включает расширенное мышление на всю сессию, проходит несколько вариантов решения, ищет подводные камни, и только потом отвечает. Используй на нетривиальных задачах, где обычный ответ будет поверхностным.

### `/loop` + Remote Tasks + HANDOFF.md — ночное расписание агентов

Anthropic выкатил команду `/loop` в марте 2026. Агент крутится в фоне как cron-джоб: выполнил итерацию, подождал, выполнил снова, пока не скажешь стоп. Уходишь спать → продолжает.

```
claude --loop "проверяй каждый час новые лиды в CRM и пиши бриф по каждому в /briefs"
```

**Главный лимит `/loop`** — работает только пока компьютер включён. Закрыл крышку ноута — агент уснул.

**Remote Tasks** (Claude.ai → Projects → Scheduled Tasks) — агент выполняется на серверах Anthropic без включённого ноутбука. Работает по расписанию.

**HANDOFF.md** — внешняя память агента между сессиями. Промпт: «после каждых 10 действий обновляй HANDOFF.md». Утром открыл один файл — за 2 минуты понял всё, что произошло за ночь.

**Пример ночного расписания (от Виаса):**
- 23:00 — забирает все звонки за день из Fathom, оценка качества, отчёт в папку
- 01:00 — мониторинг рекламных кабинетов через 3 роли (таргетолог / арбитражник / CMO)
- 03:00 — конкурентная разведка через Firecrawl, сравнение с прошлой неделей
- 06:30 — финальный брифинг в Telegram

**Лайфхак на токены:** для мониторинга и сбора данных использовать **Haiku вместо Opus** — кратно дешевле, справляется не хуже на простых задачах.

## Связь с принципами агентских систем

Этот файл — **инструмент принципа №3** из [[canon/marketing-frameworks/multi-agent-marketing-org-principles|5 принципов оркестрации]]: confidence-scored выводы и структурированные правила, закреплённые в одном месте, к которому агент возвращается каждую сессию. Без `CLAUDE.md` каждый агент на каждом запуске придумывает confidence-score с нуля, и порог валидации дрейфует. С `CLAUDE.md` правила стабильны.

Связан с [[canon/marketing-frameworks/harness-engineering-for-ai-agents|harness engineering]] как частный случай: `CLAUDE.md` — это harness для агентной работы маркетолога в Cursor/Claude Code.

## Anti-patterns

- **Энциклопедия на 500 строк** — после ~200 строк Claude начинает игнорировать правила. Вынеси справочные данные в отдельные файлы, ссылайся на них.
- **Писать код внутри CLAUDE.md** — файл для *инструкций*, не для исходников. Код живёт в проекте.
- **Копипаст одного файла между проектами без адаптации** — блок 1 и 2 обязательно проектные. Только блок 3 (стиль/тон) может быть переносим.
- **Забыть обновить блок 4 («сейчас работаем над X»)** — приводит к тому, что через неделю агент работает с устаревшим фокусом.
- **Не иметь `CLAUDE.md` вообще** — каждая новая сессия «из комы». Если вы используете Claude Code/Cursor больше 2 часов в неделю, отсутствие файла — чистый потерянный ресурс.
