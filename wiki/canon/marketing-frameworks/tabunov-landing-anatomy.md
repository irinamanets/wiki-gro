# Landing anatomy Табунова — 4-блочная структура для solopreneur-лендингов

Структурный фреймворк landing page для solopreneur/SaaS продуктов. Четыре блока, строгий порядок, никаких отступлений. Источник — founder-voice Табунова ([[sources/2026-04-14-tg-your-pet-project-jan-apr2026]] пост 573), пересекается с универсальной LPO-теорией (Unbounce, ConversionXL, Lenny's Newsletter), но формулирует в более жёсткой форме «что НЕ делать».

## Три правила, которым должен соответствовать любой лендинг

Хороший лендинг всегда делает три вещи:

1. **Отфильтровывает нецелевых.** Если тебе нужны хирурги, а на лендинг приходят школьники, правильный лендинг их отпугнёт в первые 3 секунды. Это не антипаттерн — это feature.
2. **Ведёт всегда к целевому действию, и только к нему.** Не «узнай больше» + «скачай гайд» + «подпишись на блог» + «пиши в чат». Одна страница — одно действие.
3. **Тупо и просто доносит что и кому продают.** Никаких «революционных решений для современных предпринимателей». Максимум 3 секунды на понимание «что это и для кого».

## Структура: 4 блока

### 1. Заголовок

**Коротко пишем, что за продукт.** Не «Революционное решение для современных предпринимателей», а «**Сервис рассылок в телеграме**». Чтобы даже дебил понял за 3 секунды.

Антипаттерн: использовать buzzwords («инновационный», «передовой», «умный», «AI-powered»). Они отключают читателя.

Паттерн: конкретное существительное + конкретная функция. Примеры из разобранных в [[volatile-strict/industry-news/ai-solopreneur-cases-jan-apr-2026|кейсов]]:

- «Build something Lovable» (Lovable, пост 577)
- «The most affordable Typeform alternative» (Youform, пост 589)
- «AI-агент, который пишет отклики за тебя» (Lancer, пост 551)

### 2. Боли

**Описываем словами пользователя его же боли и решаемые проблемы.**

Антипаттерн: «Наше решение повысит эффективность ваших бизнес-процессов». Это купил ChatGPT, а не живой пользователь.

Паттерн: «Надоело вручную отвечать на 200 одинаковых вопросов в день?» / «Устал каждое утро по 2 часа мониторить Upwork?» / «Каждый раз, когда сиделка отменяет смену, ты не можешь заснуть?»

**Операционный тест:** может ли пользователь сказать эту фразу вслух про себя? Если да — это его боль. Если нет — это твой копирайт.

### 3. Про продукт

**Скриншотами показываем, как работает продукт, юзер флоу и результат работы на выходе.**

Антипаттерн: «Инновационные алгоритмы машинного обучения» / «Мы используем передовые технологии».

Паттерн: нажал кнопку → получил результат → профит. Три-четыре скриншота с подписями. Никаких видео-объяснений. Никакой красивой анимации, которую нельзя прокрутить.

### 4. Call to action

**Либо лид-форма, либо прямой переход (в бот, прилу, регистрацию).**

Антипаттерны (all → помойка):

- «Узнать больше»
- «Попробовать бесплатно»
- «Start free trial»
- «Get early access»
- «Оставить заявку»

Паттерны:

- «Написать в бот»
- «Скачать приложение»
- «Зарегистрироваться»
- «Оплатить $X»
- «Connect Gmail»

CTA должен называть то **действие**, которое пользователь совершит, а не **вознаграждение**, которое он получит.

## Паттерны применения

### Для коротких лендингов (mobile-first, solopreneur MVP)

Один экран scroll:
- Hero-block с заголовком + короткой сабхедой
- 3-4 буллета болей
- 1 скриншот продукта + подпись «что ты получаешь»
- Одна CTA-кнопка
- Footer с legal

### Для длинных лендингов (B2B, высокий чек)

Та же структура, но каждый блок развёрнут:
- Hero + заголовок + video/screenshot
- Боль: 3-4 микро-истории «так было» vs «так стало»
- Продукт: step-by-step с аннотированными скриншотами
- **CTA повторяется минимум 3 раза** (после каждого раздела)
- Дополнительно: social proof, testimonials, FAQ — **но всё ещё в рамках той же 4-блочной логики**, не дополнительные сущности

### Anti-pattern длинных лендингов

- **«Hero → логотипы клиентов → features → testimonials → pricing → features → FAQ → footer»** — это аггломерат блоков без логики. Каждый блок живёт сам по себе, пользователь листает мимо.
- **Многостраничные сайты с отдельными URL под каждую фичу** — размывают фокус, добавляют шагов до CTA.

## Применение к GRO

Текущий [[canon/product-knowledge/gro-app-overview|лендинг GRO]] (groapp.ru) **в целом соответствует** структуре, но есть места для улучшения (см. [[evolving/customer-feedback/gro-app-store-reviews]] — реальные отзывы показывают, что пользователи не понимают pricing до оплаты):

1. **Заголовок** — на groapp.ru присутствует чётко, проходит тест «3 секунды».
2. **Боли** — блок testimonials частично закрывает, но в явном виде pain-раздела («Устал делать списки задач, которые никогда не выполняются?») нет. Потенциальное улучшение — добавить.
3. **Про продукт** — есть блок «4 шага», адекватно.
4. **CTA** — «Скачать в App Store» / «Скачать в Google Play» / «Скачать в RuStore» — соответствует паттерну (называет действие, а не вознаграждение).

**Contraints специфичные для GRO:**

- У GRO **три дистрибуционных стора** (см. [[canon/product-knowledge/gro-app-store-listing]], [[canon/product-knowledge/gro-google-play-listing]], [[canon/product-knowledge/gro-rustore-listing]]), а не один, поэтому CTA-блок должен включать три кнопки. Это legitimized-исключение из правила «одна CTA», потому что у пользователя разные платформы.
- Веб-кабинет [[canon/product-knowledge/gro-web-app|lk.groapp.ru]] — четвёртая точка, но её CTA **не должна** присутствовать на главном лендинге на равных с mobile-сторами (веб не раскрывает цены pre-auth, см. источник).
