# 10 шагов внутреннего news-pipeline для PR

Operational-фреймворк для **PR-функции внутри компании**: как поставить регулярную генерацию инфоповодов от других подразделений (production, R&D, HR, sales), а не вытягивать всё на себе. Источник — Pressfeed.Журнал «Как добывать информационные поводы внутри организации».

`confidence: medium` — узнаваемый organizational-паттерн, конкретный 10-шаговый список, применим в RU-контексте.

## Почему canon

Сами 10 шагов — переносимая operational-рамка для любой компании 50-500+ человек, где PR не имеет авторитета по умолчанию и нужно его конструировать. Стабильны на годы.

## Центральный тезис

PR-специалист в компании по умолчанию **не имеет доступа** к информации из других отделов. Производство не считает себя обязанным сообщать о достижениях, R&D не знает «что считать инфоповодом», sales не имеет времени делиться кейсами.

Решение — **система** из 10 шагов, которая постепенно встраивает PR в commit-rhythms компании.

## Все 10 шагов

| # | Шаг | Зачем |
|---|---|---|
| **1** | Заручиться поддержкой первого лица | Без CEO-mandate PR не имеет авторитета требовать данные у других отделов |
| **2** | Разработать документ об **информационной политике** | Формализует, что считается инфоповодом, кто и когда передаёт; снимает «а кому это надо?» |
| **3** | Приказ об обязательном соблюдении политики | Перевод документа в обязательный регламент; без него — игнорят |
| **4** | Совещание-тренинг с руководителями подразделений | Объясняет, **почему** их подразделению выгодно делиться: засветиться в СМИ, узнаваемость, PR-кредит |
| **5** | Право участвовать в оперативках и совещаниях | PR должен **знать о происходящем в реальном времени**, не постфактум — иначе инфоповод устарел |
| **6** | Регулярные встречи с CEO и руководителями ключевых департаментов | Создаёт privileged information flow и доверие |
| **7** | Копия в служебной переписке по важным проектам | Пассивный сбор фактуры, не требующий активных запросов |
| **8** | **Геймификация** — баллы подразделениям за инфоповоды → премии/подарки | Меняет экономику: «передать инфоповод» становится **выгодно**, а не «бесплатной работой» |
| **9** | Сделать ключевых сотрудников **союзниками** через нетворкинг и помощь | Soft-power: помочь R&D-инженеру с публикацией → он сам прибежит с следующим инфоповодом |
| **10** | **«Торговать публичностью»** — давать руководителям засветиться в прессе в обмен на их помощь | Прямой обмен: «я опубликую интервью с тобой в РБК → ты дашь мне доступ к данным для следующих 3 пресс-релизов» |

## Логика последовательности

Шаги **не независимы** — это нарастающий control system:

- **1-3 — формальная база** (mandate + регламент + приказ)
- **4-7 — информационная инфраструктура** (PR встроен в communication flow)
- **8-10 — экономическая инфраструктура** (мотивация и обмен ценности)

Без 1-3 шаги 8-10 не работают (нет обязательности). Без 4-7 шаги 8-10 работают, но **с задержкой** (PR узнаёт о инфоповоде через неделю). Без 8-10 шаги 1-7 работают, но **с сопротивлением** («ещё одна обязаловка»).

## Геймификация — самый недооценённый шаг

Шаг 8 — единственный, который **превращает PR-задачу в win-win**. Без геймификации:
- Production-инженер не передаёт инфоповод, потому что **не получает за это ничего**
- PR тратит время на push-запросы, что воспринимается как «PR мешает работать»

С геймификацией:
- Подразделение получает баллы → конвертируются в премии / подарки / тимбилдинг
- **Соревнование между отделами** дополнительно стимулирует

Конкретные форматы геймификации: leaderboard в intranet, ежеквартальная премия «информационный спонсор года», бонус к KPI руководителя отдела за число переданных инфоповодов.

## Anti-pattern

- ❌ Запускать pipeline **без CEO-mandate** (шаг 1) — PR упирается в «кто ты такой, чтобы требовать данные?»
- ❌ Документ-политика без приказа (шаги 2 без 3) — документ остаётся в Notion, его никто не читает
- ❌ Тренинги (шаг 4) без объяснения **выгоды для подразделений** — воспринимается как «PR навязывает обязанности»
- ❌ Геймификация без призов (декларативные баллы) — мотивация исчезает за 2 квартала
- ❌ Pipeline только через формальные шаги 1-3, без soft-power шагов 9-10 — работает на бумаге, не работает в реальности
- ❌ **«Торговать публичностью» без авторитета у СМИ** (шаг 10) — обещание «опубликую тебя в РБК» без реальной возможности убивает доверие

## Применимость к ГРО

GRO — стартап (<100 человек на момент 2026), и 10-шаговая система **избыточна**, но компоненты применимы:

- **Шаг 1 (CEO-mandate)** — критичен, особенно для запроса данных у product/dev команды
- **Шаги 2-3 (политика + приказ)** — заменяются на 1-pager в Notion с обязательностью передавать значимые release-events PR-у
- **Шаг 4 (тренинг)** — заменяется на разовый AMA «что мы публикуем и зачем»
- **Шаг 5 (право участвовать в оперативках)** — встроиться в product-standup раз в неделю
- **Шаг 8 (геймификация)** — слишком тяжёлая, заменяется на **public-recognition** в общем чате («Дмитрий из dev передал нам инфоповод про новую AI-фичу → рассказали в Skillbox Media → 50K просмотров»)

**Триггер для полного pipeline:** когда GRO вырастет до 100+ сотрудников, должна быть осознанная процедура внедрения шагов 1-10 (квартальный roadmap, OKR PR-функции).
