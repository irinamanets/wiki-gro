# MVP vs прототип — определение Горного

Каноническое различение, которое в AI-эпоху стало сильнее размываться: «MVP» всё чаще используется как синоним «alpha-версии» или «демо, которое можно показать». Александр Горный ([[sources/2026-04-14-tg-startupoftheday-mar-apr-2026]], пост 4989 от 2026-04-02) возвращает термину исходный смысл Lean Startup.

## Тезис

По мнению Горного (ex-директор по стратегии Mail.ru Group, founder [ShareAI](https://shareai.space/), 15+ лет VC/startup analysis — `confidence: medium`, inferred expert):

> **«Claude Code может собрать MVP за 5 минут» — это ложное использование термина. Это прототип, опытный образец, альфа-версия продукта. Настоящий MVP — это положительный результат проверки главной гипотезы в бизнесе.**

Разница — не в сложности кода или в том, «кликается ли оно», а в **уровне неопределённости**, которую вы снижаете построенным артефактом.

## Три типа бизнесов — три типа главной гипотезы — три типа MVP

Горный выделяет три архетипа, и MVP в каждом из них выглядит принципиально по-разному:

### 1. Стандартный продукт (товар/услуга/маркетплейс)

- **Главная гипотеза:** «клиенту это нужно» — то есть есть ли платёжеспособный спрос на конкретное предложение.
- **MVP:** полный процесс продажи. Стартап нашёл покупателя, взял с него деньги, выдал результат в таком качестве, чтобы потребитель был хотя бы минимально удовлетворён. Процесс воспроизводим (следующего клиента можно найти с теми же усилиями).
- **Что MVP НЕ требует:** прибыльности, сходимости unit-экономики, готовности к масштабированию. «Если на каждой продаже вы теряете по миллиону — это плохой MVP, но всё ещё MVP.»
- **Типичная подмена:** лендинг с формой + кликабельный прототип ≠ MVP. Если никто не заплатил — гипотеза не проверена.

### 2. Deep-tech / «невозможное»

- **Примеры:** вечный двигатель, пересадка мозга, самосборная мебель, нейрочип, новый тип аккумулятора.
- **Главная гипотеза:** *физически возможно* это сделать с заявленными характеристиками.
- **MVP:** сам работающий образец. «Вечный двигатель есть, энергия не потребляется, но выдаётся — всё, победа, продать такое "каждый дурак" сможет.»
- **Что MVP НЕ требует:** масштабируемости производства, себестоимости, маркетинг-канала. Эти вопросы — следующие этапы.
- **Типичная подмена:** PowerPoint с графиком «как будет работать» ≠ MVP.

### 3. Медиа / соцсеть / бесплатный сервис

- **Главная гипотеза:** люди приходят и остаются. Монетизация — отдельный вопрос следующего уровня.
- **MVP:** виральный рост + удержание. «Вы привели на сайт 100 человек, через неделю пришли 20, а не ноль — да, какая-то ценность есть, гипотеза "люди будут приходить" проверена.»
- **Что MVP НЕ требует:** монетизации, unit-экономики, даже объёма. Важна **удерживаемость**, а не абсолютный размер первой волны.
- **Типичная подмена:** красивый лендинг + 10k уникальных визитов от платной рекламы ≠ MVP. Retention — ключевая метрика, а не первичный трафик.

## Почему это важно в 2026 году

Горный явно указывает на AI-эпоху как на источник путаницы: Claude Code, Cursor и смежные инструменты **радикально удешевили** постройку прототипа — функционального кликающегося куска софта с реальной базой данных и авторизацией. Это **не снизило стоимость MVP**, потому что MVP — не про код, а про **проверенную рыночную гипотезу**.

Фольклорная формулировка Горного из того же поста:

> «Ничего из этого AI пока сам в один запрос не делает. Уж не знаю, что будет через пять лет, но пока — нет.»

Прикладное следствие: команды, которые путают прототип с MVP, тратят раунды инвестиций и месяцы на «запуск», которого по факту не было. С точки зрения продуктового маркетинга это означает, что перед любым масштабированием канал-миксов (paid ads, content, PR) **нужно проверить, что у вас на руках реально MVP**, а не прототип — иначе вы льёте трафик на непроверенную гипотезу.

## Связь с другими фреймворками

- **Lean Startup (Eric Ries, 2011).** Горный по сути пересказывает ранние определения Ries'а через 15-летнюю призму, уточняя их в AI-контексте. Это не новый фреймворк, а re-articulation.
- **CastDev / Demand-First.** См. [[canon/marketing-frameworks/demand-first-mvp-castdev]] — смежный подход «спрос первым, продукт вторым». Горный усиливает эту логику: «полный процесс продажи» в архетипе #1 — это буквально demand-first MVP.
- **CPA Calculator / Pre-launch ROI.** См. [[canon/marketing-frameworks/cpa-calculator-pre-launch-roi]] — после прохождения MVP-барьера можно считать экономику канала.
- **Funnel simplicity principle.** См. [[canon/marketing-frameworks/funnel-simplicity-principle]] — воронка строится **после** MVP, не до.

## Применение в GRO-контенте

Для [[canon/target-audience/gro-segments|сегментов ЦА GRO]] (карьеристы, предприниматели, фрилансеры) это различение даёт готовую **объекцию-hook** против конкурентов и против «прототип-инфляции»:

- **Hook для предпринимателей:** «Claude Code собрал твой сайт за вечер. Это не MVP. MVP — это когда ты взял с клиента деньги и он вернулся за вторым.»
- **Anti-hook:** не использовать в постах GRO оборот «мы запустили MVP за выходные» — это дешёвый маркер прототип-мышления, Горный и аналогичные эксперты такие формулировки снимают.
- **Нарратив для anti-positioning:** GRO как продукт **про действия, а не про знания** (см. [[canon/positioning/gro-value-proposition]]) резонирует с идеей «MVP — это результат на рынке, а не кликабельная демка». Это можно использовать в контенте: «Знать про MVP ≠ иметь MVP. Читать книги про рост ≠ расти.»

## Что может сдвинуть определение

- **Через полгода–год:** если AI-агенты начнут сами находить клиентов, брать деньги и обслуживать сделку end-to-end — то пункт «Claude Code в один запрос не делает MVP» станет ложным для архетипа #1, и определение потребует обновления. Сейчас (апрель 2026) — ещё нет.
- **Для B2B-SaaS в enterprise:** есть аргумент, что архетип #1 там смешивается с архетипом #2 (технологическая осуществимость + регуляторика), и MVP выглядит иначе. Горный этот случай не разбирает, остаётся открытым.
