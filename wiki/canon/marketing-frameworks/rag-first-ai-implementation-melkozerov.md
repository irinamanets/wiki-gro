# RAG-first AI implementation playbook (Мелкозёров)

Методологический подход к внедрению AI в компанию, сформулированный **Егором Мелкозёровым** (основатель компании «Спокойствие и Уверенность») в статье на Cossa.ru ([trends/348208](https://www.cossa.ru/trends/348208/)), процитированной в [[sources/2026-05-05-tg-cossaru-apr-24-may-5-2026]] пост 23104. Атрибуция автора: practitioner-консультант, конкретный бизнес-кейс приведён на 10+ ресторанов с 15-летней историей. `confidence: medium` — экспертное мнение с подкреплением реальным кейсом, но независимая верификация результата отсутствует.

## Главный тезис

> **«Не начинайте внедрять AI, пока не разберётесь с RAG. Иначе любые AI-трансформации обречены»** — Егор Мелкозёров, [[sources/2026-05-05-tg-cossaru-apr-24-may-5-2026|пост 23104]]

## Проблема, которую решает фреймворк

Десятки компаний начинают AI-трансформацию с **витринных решений** (чат-боты, агенты, автоматизация процессов), но сталкиваются с одинаковой проблемой:

- **Модель умная, демонстрация красивая, но реальной бизнес-ценности нет**, потому что **системе просто не на что опереться внутри самой компании**

То есть AI без структурированного корпоративного знания работает либо **на общедоступных данных** (теряя domain-specific ценность), либо **на хаотичной выборке внутренних документов** (выдавая некорректные ответы).

## Принцип: знание — фундамент, агенты — надстройка

Структура AI-внедрения по Мелкозёрову:

```
[Слой 4]   AI-агенты, автоматизация workflow'ов
[Слой 3]   Применения (чат-боты для команды, ассистенты)
[Слой 2]   ★ Корпоративная RAG-инфраструктура (фундамент)
[Слой 1]   Структурированное корпоративное знание (источники)
```

**Критический инвариант:** строить сверху-вниз нельзя. Слой 2 (RAG) должен существовать до того, как имеет смысл строить слои 3–4.

## База-кейс: ресторанная группа

Применение фреймворка на конкретном кейсе (приведён в статье):

| Параметр | Значение |
|---|---|
| Тип бизнеса | ресторанная группа |
| Количество заведений | 10+ |
| Возраст бизнеса | 15 лет |
| Объём корпоративного знания | 1000+ документов |
| Платформа знания | Notion |
| Ключевые элементы | роли, безопасность доступа, иерархия документов |

**Подход:** сознательный отказ начинать с агентов, витрин, автоматизации. Сначала — **корпоративная RAG-инфраструктура как фундамент** AI-архитектуры. На этом фундаменте затем запускались agents и automation.

## Что делает RAG-инфраструктуру «корпоративной»

Из материала следуют четыре характеристики `[conf:medium, src:2026-05-04]`:

1. **Объём ≥1000 документов** — критическая масса для того, чтобы RAG имел измеримую ценность над сырым LLM
2. **Хранилище с ролевой моделью** (Notion в кейсе) — разные роли получают разные срезы знания
3. **Безопасность доступа** — RAG не должен утечь чувствительные данные сотрудникам без права
4. **Регулярная обновляемость** — знание устаревает, RAG требует процесса синхронизации

## Применимость для GRO

GRO как AI-продукт сам строит подобную архитектуру для пользовательского AI-агента. Принципы Мелкозёрова применимы как **внутренняя organizational дисциплина** GRO-команды, так и как **content-frame** для маркетинга.

### 1. Внутренняя дисциплина GRO

Маркетинг GRO работает с большим объёмом research-материалов (этот wiki — сам по себе пример), и принципы RAG-first применимы:

- **wiki/sources/** — структурированное корпоративное знание (Слой 1)
- **wiki/<layer>/<theme>/** — RAG-индекс (Слой 2)
- **wiki-query agent** — агент-надстройка, использующий RAG (Слой 4)

Параллель с [[canon/marketing-frameworks/harness-engineering-for-ai-agents]] и [[canon/marketing-frameworks/spec-driven-agent-development]] — wiki marketing-memory **самим своим устройством** реализует RAG-first принцип.

### 2. Content-frame для маркетинга

GRO-аудитория (предприниматели, топ-менеджеры) сейчас активно ищет ответ на вопрос «как внедрить AI». RAG-first frame — **сильный contrarian-hook против витринных решений**:

- **«AI без базы знаний — это демо, не бизнес»** — Hook для awareness-уровня. Connects с уже задокументированным [[evolving/content-trends/ai-control-dystopia-counter-hook]] (anti-hype framing).
- **«Начните с того, что у вас уже есть — с ваших данных. И только потом — с агентами»** — pull-hook для consideration-уровня. Connects с [[canon/marketing-frameworks/ankusheva-ai-implementation-triad]] (методологический параллель).
- **«1000+ документов в Notion с ролевой моделью важнее, чем самый крутой чат-бот»** — concrete-hook с цифрой `[conf:medium, src:2026-05-04]`.

### 3. Дифференциация GRO как AI-продукта

GRO как fitness-AI — это применение RAG-принципа к **личным данным пользователя**: история тренировок, биометрия, цели, предпочтения. **GRO без personal-RAG — это generic AI, какой даёт ChatGPT**. Это содержательное обещание дифференциации.

Параллель с [[canon/marketing-frameworks/ai-personalization-4-layer-architecture]] — там описана 4-слойная архитектура personalization, RAG-first Мелкозёрова — это её **organizational аналог** на корпоративном уровне.

## Контр-аргумент / caveat

- **Мелкозёров — practitioner, не академик.** Атрибуция: founder агентства, практикующий консультант. Это `confidence: medium`. Ригорозный академический эмпирический тест RAG-first в индустрии **не известен** на момент 2026-05-05. Не использовать как «доказанный фреймворк».
- **«1000+ документов» как порог эмпиричен.** В кейсе ресторанной группы. Для GRO-командного применения порог скорее всего ниже (~100–300 документов RAG уже даёт смысл).
- **Notion как платформа** — продакт-выбор Мелкозёрова. Альтернативы: Confluence, Coda, Obsidian, file-based markdown wiki (как этот). Для GRO выбор должен исходить из team-tooling-stack, не из «Notion как best practice».
