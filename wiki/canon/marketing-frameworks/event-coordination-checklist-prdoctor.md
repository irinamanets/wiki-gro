# Event-coordination checklist (PR DOCTOR)

**Тезис.** Выставки, конференции, форумы — один из самых эффективных B2B-инструментов. Они решают задачи всех трёх отделов **одновременно**: продажи получают короткий путь к ЛПР, маркетинг тестирует гипотезы, PR находит инфоповоды и каналы коммуникации.

Но **за 17 лет в продажах и маркетинге** автор статьи PR DOCTOR «по пальцам полутора рук может пересчитать случаи, когда к мероприятию готовились сообща» ([[sources/2026-05-19-pressfeed-prdoctor-marketing-pr-sales-conflict]]).

Это **операционализация Рычага 1** («зафиксировать роли письменно») из [[canon/marketing-frameworks/three-dept-conflict-prdoctor|3-департаментного конфликта]] на конкретном repeating-use-case.

## Anti-pattern: «каждый отчитывается за своё»

**Что обычно происходит:**
- **Продажники** обзванивают все собранные на выставке визитки
- **Маркетинг** отчитывается по охватам в соцсетях (посты с мероприятия)
- **PR** — по количеству вышедших публикаций о мероприятии
- → **Никто не понимает, каков был совокупный эффект и реальная отдача от вложенных средств**

Те же три отдела, что в обычной операционке конкурируют → на мероприятии параллельно решают **каждый свою задачу**, не сводя результат.

## Best-practice: 5 вопросов, фиксируемых **до** мероприятия

Эти 5 вопросов должны быть **зафиксированы письменно** и иметь конкретных ответственных **до** начала события:

### Вопрос 1 — Кто заранее смотрит списки участников и назначает встречи?

- Обычно делает: PR + продажи (PR знает кто в индустрии, продажи знают целевых ЛПР)
- Артефакт: список приоритетных контактов с пометкой кто из своих с кем встречается
- Тайминг: за 2-3 недели до события (раньше — списки ещё неполные, позже — у целевых уже расписан график)

### Вопрос 2 — Кто организует комфортное место для переговоров?

- Обычно делает: маркетинг (logistics-функция, опыт стенд-organisations)
- Артефакт: бронь переговорки/стенда, пометка кто куда подходит
- Без этого: встречи проходят «на ходу», ЛПР не запоминают, контакты теряются

### Вопрос 3 — Кто готовит правильные единые презентационные материалы и скрипты для команды?

- Обычно делает: **PR** (смыслы и формулировки) + маркетинг (визуальные материалы) + продажи (продуктовые аргументы)
- Артефакт: единый pitch-deck + 30-сек / 2-мин / 5-мин версии скрипта в зависимости от глубины разговора
- Без этого: каждый продаёт «своими словами», ЛПР получают противоречивые сообщения о продукте

### Вопрос 4 — Как будет оперативно фиксироваться обратная связь от посетителей?

- Обычно делает: продажи (на месте) + маркетинг (форма для CRM)
- Артефакт: единая структура заметки по каждому контакту (роль, компания, обсуждённая тема, температура интереса, next-step, дата следующего касания)
- Без этого: визитки складываются в кучу, через неделю никто не помнит контекст разговора

### Вопрос 5 — Какие именно данные нужно собрать «в полях»?

Это **самый важный вопрос для последующей квалификации лидов и точного расчёта конверсии**. Без этих данных невозможно посчитать ROI мероприятия.

**Минимальный набор:**

| Поле | Зачем |
|---|---|
| Роль / должность | Quality-классификация лида |
| Компания + индустрия | Сегментация для маркетинга |
| Обсуждённая тема / интересующий use-case | Качество, не количество (см. [[canon/marketing-frameworks/hot-lead-share-kpi-vtochku|hot-lead-share]]) |
| Температура (cold / warm / hot) | Приоритизация follow-up |
| Согласованный next-step (звонок / письмо / демо / просто follow / nothing) | Action-bias |
| Дата next-step | SLA по реакции |

**Без согласования этого формата** на месте каждый продажник заполняет своё → данные несопоставимы → маркетинг не может посчитать конверсию по сегментам.

## После мероприятия: единый сводный отчёт

После мероприятия — **не три отчёта** (PR-отчёт о публикациях, маркетинг-отчёт об охватах, sales-отчёт о звонках), а **один совместный**:

- Все вместе сели
- Свели общий отчёт
- Посчитали конверсию (контакт → встреча → демо → КП → сделка)
- Проанализировали **общий** результат

Это операционализирует [[canon/marketing-frameworks/three-dept-conflict-prdoctor#Рычаг 3 — Поменять KPI с узких на системные (Revenue KPIs)|system-KPI принцип]] на проектном уровне.

## Применение к GRO

GRO продаёт два продукта одновременно: подписку 2 490 ₽/мес (B2C, lidogen через маркетинг) и Интенсив (high-ticket B2B, требует sales-цикла). Event-coordination применим **прежде всего для Интенсива** на профильных HR/L&D-мероприятиях:

- **Списки участников** — заранее находить HR-директоров и L&D-руководителей среднего и крупного B2B
- **Переговорка** — обязательна для Интенсива (демо групповых тренировок, обсуждение программы под клиента)
- **Скрипты** — Интенсив требует другого pitch чем приложение: акцент на ROI команды, retention soft skills, корпоративный формат
- **Данные** — Lead-qualification поля для B2B (размер команды для тренировок, бюджет L&D, decision timeline)
- **Сводный отчёт** — конверсия из event-контакта в подписанный Интенсив-договор (типичный B2B-цикл 1-3 месяца, нужна attribution-модель)

Для приложения event-coordination применим в меньшей степени — там основная воронка через paid-ads и контент-маркетинг.

## Anti-patterns

- ❌ **«Все собрались на выставке — после посчитаем»** — без pre-event coordination данные после несовместимы
- ❌ **Три отчёта параллельно** (PR + маркетинг + продажи) — невозможно посчитать общий ROI
- ❌ **«Скрипты не нужны, мы опытные продажники»** — без единых смыслов от PR команда продаёт разное
- ❌ **«CRM-форма заполним вечером»** — память деградирует в течение часа после разговора, нужна on-the-spot фиксация
- ❌ **Бронь переговорки в день мероприятия** — поздно, переговорные забронированы за недели
