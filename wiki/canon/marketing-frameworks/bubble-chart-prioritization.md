# Bubble-chart prioritization: 3 переменные для выбора мероприятий

Визуально-числовой метод приоритизации мероприятий по продукту или маркетингу: каждая инициатива оценивается по трём переменным и наносится на 2D-график с переменным размером пузыря. Развитие классического матрицы Eisenhower (urgent×important) с добавлением размера пузыря для третьей переменной.

## 3 оси

| Ось | Что измеряет | Шкала |
|---|---|---|
| **X** | Рейтинг (влияние мероприятия на потребительские свойства продукта) | 1-10 или low/med/high |
| **Y** | Время на проведение | дни / недели / месяцы |
| **Размер пузыря** | Стоимость реализации | руб / диапазон |

## 4 квадранта

| Квадрант | Описание | Действие |
|---|---|---|
| **«Быстро и эффективно»** | Высокий рейтинг + малое время | Приоритет 1 — делать сейчас |
| **«Долго но эффективно»** | Высокий рейтинг + большое время | Параллельный трек / следующий квартал; разбить на этапы |
| **«Быстро но бесполезно»** | Низкий рейтинг + малое время | Quick-wins только если ресурс свободен; иначе пропустить |
| **«Долго и бесполезно»** | Низкий рейтинг + большое время | Исключить — даже не обсуждать |

Размер пузыря добавляет тонкую настройку: при равных X-Y предпочитать меньшие пузыри (дешевле). Большой пузырь в «долго и бесполезно» — особо опасное мероприятие, которое нельзя пропустить мимо «исключить».

## «Коэффициент проблемности»

Для определения **рейтинга на оси X** (влияния на потребительские свойства) используется производный показатель:

> **Коэффициент проблемности** = важность свойства для потребителя / удовлетворённость свойством сейчас

Если важность 5 баллов из 5, а удовлетворённость 1 балл — коэффициент 5 (горящая проблема). Если важность 2, удовлетворённость 5 — коэффициент 0.4 (overinvestment, не приоритет).

→ Мероприятие, улучшающее свойство с высоким коэффициентом проблемности, попадает в правую часть оси X. Мероприятие на свойство с низким — в левую часть.

## QFD-Hoshin корреляционная шкала

При оценке **корреляции мероприятия со свойством** используется 5-балльная шкала +9, +3, 0, -3, -9:

| Балл | Значение |
|---|---|
| **+9** | Мероприятие сильно улучшит свойство |
| **+3** | Улучшит |
| **0** | Никак не повлияет |
| **-3** | Ухудшит свойство |
| **-9** | Сильно ухудшит |

Шкала намеренно неравномерная (9 / 3 / 0): это стандарт Quality Function Deployment / Hoshin Kanri. Большая разница между «никак» и «улучшит» (×3) и между «улучшит» и «сильно улучшит» (×3) — заставляет команду давать радикальные оценки, а не размывать всё по середине.

## Применимость к GRO

- **Roadmap-планирование:** все candidate-мероприятия раз в квартал визуализируются на bubble-chart → топ-5 в «быстро и эффективно» становятся приоритетами на квартал
- **Marketing campaign portfolio:** приоритизация креативных идей и каналов через bubble (рейтинг = ожидаемое влияние на awareness/CTR; время = до запуска; стоимость = production+media budget)
- **Product feature voting:** замена «голосования» на структурированную оценку с коэффициентом проблемности — снижает влияние loud-voice внутри команды
- **Anti-pattern:** «у нас лот идей и все важные» = команда не делала bubble-chart. Гарантированно есть «долго и бесполезно» в списке, которые тратят ресурс.

## Когда bubble-chart недостаточен

- При зависимостях между мероприятиями (одно открывает возможность другому) — bubble не отражает зависимости. Дополнять Gantt или dependency-graph.
- При мероприятиях с разными рисками — единый axis «рейтинг» не различает «10 баллов на 90% случаев» и «10 баллов на 30% случаев». Дополнять risk-adjusted scoring.
