# 5 принципов экологичного AI-prompting

Прескриптивный фреймворк для использования LLM (ChatGPT, Claude, Gemini, GigaChat) в задачах генерации текста, опубликованный @rff_channel в посте 4384 (2026-04-27) после интерпретации [[evolving-strict/market-data/ai-resume-acceptance-rff-poll-2026|опроса 543 голосов]]: **74% HR ок с AI-резюме, но 6% триггерятся именно на признаки «шаблонного AI-output»**.

Хотя оригинальный пост касается AI для резюме, принципы — **переносимые на любой prompting-task**: подбор копирайтинга, генерация рекламных hook'ов, переписки с клиентом, описаний продукта. Это **canon-frame для маркетолога**, а не «как сделать резюме».

## Главный концептуальный сдвиг

> **AI — это не аутсорс, AI — это инструмент. За финальный результат отвечает человек.**

Из RFF: «Триггерит не ИИ, а шаблонность, странный язык, перегруженные формулировки и "креатив" со спецсимволами». То есть rejection-сигнал в HR-воронке (и **в любой другой воронке**, где результат читает человек) — **не сам факт использования AI, а признаки нерефлексивной генерации**: длинные формулировки, авто-bullet-points, AI-симптомные символы.

См. cross-link: [[canon/marketing-frameworks/ai-text-markers-checklist|12 маркеров AI-текста (Pressfeed)]] — те же признаки, которые читатели опознают как «шаблонность».

## 5 принципов

### 1. Давайте чёткую задачу — не «улучши», а пример целевого результата

**Анти-паттерн:** «Улучши моё резюме», «Сделай продуктовое описание лучше», «Напиши пост в Telegram».

**Pattern:** загрузите в LLM **пример** того, к чему хотите прийти (пост-образец, резюме коллеги, конкурентское описание), и сформулируйте: «Сделай мой текст в **таком же** стиле и структуре».

**Почему работает:** LLM хорошо имитирует, плохо изобретает. Когда нет образца, модель собирает «среднее по всем виденным в обучении» → **это и есть «шаблонный AI-output»**.

**Маркетинговое применение:** при генерации hook'ов для постов — давать LLM 3-5 примеров hook'ов, которые уже работали в нише (с метриками, если есть). При генерации описания продукта — давать конкурентский референс + явную инструкцию «но звучи **не так**, найди свой угол».

### 2. Задавайте структуру сами — заранее определите блоки

**Анти-паттерн:** «Сгенерируй мне резюме» (LLM сам выбирает структуру → шаблонная).

**Pattern:** заранее опишите блочную структуру:
- Контакты
- Саммари (2-3 предложения)
- Опыт (самое важное)
- Образование
- Основные навыки
- Доп. информация

И поручите LLM **наполнить ваши блоки**, а не структурировать с нуля.

**Маркетинговое применение:** при генерации лендинга — задавать блоки (hero / pain / solution / proof / CTA) явно, попросив LLM наполнить **только** в этих рамках. При создании поста — задать «хук → раскрытие → анти-paтtern → CTA», не «придумай пост».

### 3. Работайте по блокам — попросите LLM задавать вопросы

**Анти-паттерн:** «Вот мой опыт целиком, генери резюме» (LLM получает много контекста сразу → теряет деталь, обобщает).

**Pattern:** инверсный prompting — попросите LLM **задавать вам вопросы по каждому блоку**:
- Позиция
- Компания (индустрия, размер, департамент, география)
- Задачи
- Достижения с цифрами
- Влияние на бизнес (если можно померить метрикой)

После заполнения каждого блока — LLM собирает финальный вариант.

**Почему работает:** структурированный input → структурированный output. Это **conversational engineering**: LLM не угадывает, что важно, а вытягивает из вас детали.

**Маркетинговое применение:** при создании tone-of-voice guide — поручить LLM задавать вопросы про бренд (миссия, аудитория, табу, любимые слова). При работе над позиционингом — итеративный диалог с фиксацией каждого блока, а не «вот информация о компании, пиши позиционинг».

### 4. Чистите язык и символы — убирайте AI-маркеры

**Анти-паттерн:** оставлять в финальном тексте `—`, `→`, `↑`, `↓`, `~`, эмодзи-bullet-points, длинные параллельные структуры. Это **AI-style markers**, читатели их опознают и снижают доверие.

**Pattern:** после генерации — пройтись и **заменить**:
- `—` (em-dash, AI-симптом) → обычное `-` или перефраз без тире
- `→` `↑` `↓` → словами «к», «вверх», «вниз»
- Эмодзи-bullets, если в исходном стиле читателя их не было
- Длинные параллельные структуры («Не А. Не Б. Не В.») → smoothed prose
- Лишние «**в заключение**», «**подводя итог**», «**в свою очередь**» — AI-связки

См. полный список в [[canon/marketing-frameworks/ai-text-markers-checklist|12 маркеров AI-текста]].

**Маркетинговое применение:** обязательный шаг перед публикацией. Минимум 1 проход глазами + поиск по типичным символам.

### 5. Финальную версию собирайте сами

**Анти-паттерн:** «Сгенерируй финальный PDF», «Дай готовый текст для публикации».

**Pattern:** LLM производит **черновик блоков**, человек **собирает их в финал**:
- Удаляет лишнее
- Перефразирует, чтобы звучало вашим голосом
- Проверяет факты (особенно числа — LLM галлюцинирует)
- Форматирует под целевую платформу

**Почему работает:** ответственность за финал = ваша. AI помогает с черновиком, **финал = вы**. Это и юридический момент (см. [[evolving/industry-trends/ai-replacing-jobs-global-2026|Counter-anchor РБК Pro 29.04.2026 — иски работодателей за AI-сгенерированную плохую работу]]) и качественный.

**Маркетинговое применение:** не нажимать «опубликовать» сразу после генерации. Минимум — пауза, перечитывание, вычищение, fact-check.

## Concept-summary

| # | Принцип | Анти-паттерн | Эффект на качество |
|---|---|---|---|
| 1 | Чёткая задача с примером | «Улучши» без референса | Уход от шаблонного «среднего по всем» |
| 2 | Структура от вас | «Структурируй с нуля» | Сохранение вашего angle |
| 3 | Iterative по блокам | Massive context dump | Сохранение деталей, нет over-generalization |
| 4 | Чистка маркеров | Оставление `—`, `→` | Снятие AI-stigma в восприятии |
| 5 | Финал — человек | «Готовый текст» | Ответственность за качество + fact-check |

## Перенос на маркетинговые задачи (не только резюме)

Принципы применимы за пределами резюме:

- **Создание контента в TG / блогах.** Pattern: «вот 5 постов нашего канала, которые зашли по reach (с метриками); сделай 6-й в таком же стиле, тема X». См. [[evolving/content-trends/telegram-native-formats]] про вариативность стилей.
- **Описания продуктов / категорий.** Pattern: «вот 3 описания конкурентов; сделай наше — но **отличающееся** на edges A, B, C». Параллель — [[canon/marketing-frameworks/llm-market-analysis-prompt]] (применение тех же принципов в маркет-исследовании через LLM).
- **Email-цепочки welcome / nurture.** Pattern: задать сценарий писем явно, потом наполнять каждый — не «сгенерируй welcome-цепочку».
- **Performance-копирайтинг (рекламные hook'и).** Pattern: дать LLM 10 hook'ов из контрольной кампании + метрики; попросить **варианты** в той же логике, не «hooks с нуля».
- **Tone-of-voice guides.** Pattern: iterative dialogue с LLM (принцип 3) — модель задаёт вопросы, вы отвечаете, она в конце собирает.

## Anti-patterns (что НЕ делать)

- **Не делать LLM «единственным co-author»** — на любом этапе должен быть human-pass для качества и fact-check.
- **Не игнорировать дрейф моделей.** Что было «хорошо» в марте может звучать «штамповано» в октябре, потому что аудитория научилась распознавать стиль модели. См. [[evolving/content-trends/ai-text-detection-landscape-2026]].
- **Не использовать AI на критичных текстах без двойного fact-check.** LLM галлюцинирует — особенно числа, юридические формулировки, имена.
- **Не путать «AI помог» с «AI написал».** В первом случае ответственность ваша, во втором — никакой защиты от низкокачественного output.
- **Не строить вайбкодинг-style continuous-output workflow на критичных задачах.** Для маркетинговых черновиков OK, для legal claims, market analysis, performance creatives — нет.
