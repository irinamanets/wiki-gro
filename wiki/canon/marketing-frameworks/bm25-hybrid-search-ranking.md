# BM25 и гибридный поиск

Объяснение базового алгоритма ранжирования текстового поиска из обучающего поста @techno_yandex (пост 5272, 2026-05-25). Релевантно маркетологу как **фундамент понимания SEO/GEO/AEO и поиска по маркетплейсам**: знать, по каким сигналам ранжируется контент, — условие для оптимизации видимости. Источник — [[sources/2026-05-26-tg-techno-yandex-may-20-25-2026]].

## Что такое BM25

**BM25** (Best Matching, версия 25, опубликована в 1994 г.) — алгоритм ранжирования документов по релевантности запросу. К середине 2010-х стал мировым стандартом; его использовали интернет-поисковики вроде Google (сейчас они работают на более сложных алгоритмах). Но на BM25 **до сих пор основано большинство локальных систем поиска** — например, поиск по маркетплейсам.

Текстовый поиск решает задачу в два этапа:
1. **Отбор** — система находит документы со словами из запроса.
2. **Ранжирование** — сортирует их по убыванию релевантности. За второй шаг часто отвечает BM25.

## Три критерия оценки релевантности

BM25 оценивает релевантность каждого документа по отдельным словам запроса. Пример запроса: «пирог с яблоками и корицей».

1. **Редкость слова (IDF).** Чем реже слово встречается в базе, тем сильнее сигнал. «Корица» встречается редко — сильный сигнал; «яблоки» чаще — сигнал слабее; союз «и» есть везде и на оценку не влияет.
2. **Частота слова с защитой от накрутки (TF saturation).** Тройное упоминание «корицы» повысит релевантность, но 30 повторов уже не завысят оценку — алгоритм устойчив к keyword stuffing.
3. **Длина документа.** Короткая карточка и большой лонгрид — разные весовые категории. BM25 выравнивает это, чтобы точный короткий рецепт не проиграл объёмной статье «История яблочных пирогов».

Каждый критерий — числовое значение, которое подставляется в итоговую формулу; она ставит оценку релевантности, на которой строится выдача.

## Почему ИИ-поиск не заменил BM25

BM25 закрывает слепые зоны нейросетей. Артикулы, коды ошибок, имена функций — то, что для нейросети может быть числом без контекста, для BM25 конкретное слово: либо есть в документе, либо нет. Поэтому сейчас он часто работает **в паре с ИИ**: один ищет по словам, второй по смыслу, а результаты объединяют. Так устроен **гибридный поиск**, на котором построено большинство [[canon/marketing-frameworks/rag-first-ai-implementation-melkozerov|RAG-систем]].

## Маркетинговые выводы

- **Anti-stuffing урок.** Защита от накрутки в BM25 объясняет, почему повтор ключа в тексте не работает: алгоритм насыщается. Релевантность тянут **редкие точные термины**, а не частота.
- **Длинный текст ≠ выше ранг.** Нормализация по длине означает, что раздутый лонгрид не выигрывает у точного короткого ответа — аргумент за концизный, плотный по фактуре контент.
- **GEO/AEO контекст.** Гибридный поиск (BM25 + векторный) — это реальная механика за AI-Overviews и поиском по базам. Структурированные точные данные (артикулы, термины) важны для лексического слоя, смысловая полнота — для векторного. См. [[canon/marketing-frameworks/object-oriented-retrieval-kravchenko]] и [[evolving/industry-trends/ai-search-aeo-geo-2026]].
- **Маркетплейсы.** Карточка товара ранжируется по BM25-логике: редкие точные атрибуты в названии/описании сильнее общих слов.
